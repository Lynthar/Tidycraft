# Changelog

All notable changes to Tidycraft will be documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once it leaves alpha.

## [Unreleased]

### Added
- **A real menu bar on macOS.** The app used to show Tauri's fallback menu — About, the clipboard roles and Quit, with a File menu whose only entry was Close Window: nothing in the bar could open a project, rescan, or reach Settings. The bar now carries the app's actual surface — Open Project with the recent-projects list, Rescan and Run Analysis, the three views, the command palette, Settings, and GitHub help links — and follows the interface language. Every shortcut the menu declares routes through the same guards as the in-app keyboard handling, because on macOS the menu owns those keystrokes outright. Windows and Linux are untouched; the in-window header already fills this role there.
- **The asset list can be used from the keyboard.** Choosing a file was mouse-only: the rows were not focusable and no key moved between them, so someone working from the keyboard could reach the toolbar, the search box and the sort headers but never the files themselves. A down arrow in the search box now moves into the list — and so does Tab, wherever the system allows it: macOS keeps full keyboard navigation behind a setting that is off out of the box and honours it for everything that is not a text field, so Tab on its own would have left the files out of reach there. The arrow keys then walk through the list and preview as they go, Home and End reach the ends, and the page keys move a screen at a time. Holding Shift while moving takes a run of files into the selection the rename, move and delete actions read; ticking an individual file into or out of that selection is done with the mouse. Enter opens the file with whatever the system opens it with. Tabbing through the list on the way somewhere else deliberately leaves the preview alone — only the arrow keys change what you are looking at, which is also why arriving with the down arrow puts the cursor back on the row it was last on. Losing the file under the cursor no longer resets the list to the top, whether it went from a keyboard action or after a mouse click: the cursor stays near where it was, though when a whole run of rows disappears at once it can land a little past them rather than exactly on the next one.

### Changed
- **The window no longer shrinks to a size the layout cannot survive.** The declared minimum was 800×600, and at that size the app was not actually usable: the toolbar squeezed its own controls into vertical wrapping, the sort and view switches were clipped, and the issue page set action labels one character to a line. The minimum is now 1000×700 — the smallest size the three-panel layout genuinely fits. A truly narrow layout, with a collapsing toolbar and overflow menus, remains future work; until it exists the window simply will not pretend.
- **`@` is no longer a forbidden filename character by default.** The naming rule shipped with `@` in its default forbidden set, flagged as auto-fixable — but `@` is a convention character, not a hazard: `@2x` names every retina image, and Unity reads `model@walk.fbx` as its animation-clip convention. Scanning this repository with its own defaults produced exactly one finding: a proposal to rename Tauri's high-resolution icon, which would have broken the next build. The space stays flagged — it genuinely breaks texture resolution in the app's own 3D preview and is disallowed in Unreal asset names. A pipeline that forbids `@` can put it back in `tidycraft.toml`.
- **Four keyboard shortcuts were retired.** Duplicating the current selection, running the analysis, switching between the Assets, Issues and Stats views, and entering full screen no longer have a keystroke bound to them; the Fullscreen menu item is gone outright, since a predefined menu item's accelerator is assigned by the system and there was no way to keep the item and drop the key. None of the four actions themselves went anywhere: duplicate is still on the right-click menu, Run Analysis is still a click on its sidebar button or an entry in the command palette, the three views still switch from the sidebar tabs or the command palette, and full screen is still reachable from the window's own green button.

### Fixed
- **The keyboard can delete the checked files on a Mac.** The shortcut listened for the Delete key, which on a Mac's main keyboard is not the key labelled delete: that one reports a backspace, and the key that does report Delete is Fn+Delete on the few keyboards that have it at all. So the shortcut existed and could not be pressed. macOS now uses ⌘⌫, the chord the Finder itself moves files to the trash with; Windows and Linux keep Delete. Backspace on its own still does nothing, deliberately — it is a key people press to erase a character, not to send files to the trash.
- **A long error no longer pushes Retry and Dismiss out of the status bar.** The bar is a single 28-pixel row and the error text was free to take as much of it as it wanted — a backend message carrying a full path could run past the window edge, taking both buttons with it, so the error could neither be retried nor dismissed. The message now truncates and carries the full text in its tooltip; the buttons keep their place.
- **A project that fails to open now says so.** The failure came before the project had anywhere to report it, so the only record was a line in a console a packaged application has nowhere to show: you picked a folder and the app did nothing at all. It now reports the reason.
- **Tags survive a rename made before you have opened the tag panel.** Renaming, moving or undoing a rename carried the file's tags only if something had already read the tags file in that session — otherwise the binding stayed on a path that no longer existed, and the first thing to read the file afterwards handed it to the watcher's orphan cleanup, which deleted it. Nothing warned, and nothing about it was visible until the tags were already gone. It held up in ordinary use only because opening a project and reaching for the tag panel usually came first; restoring a session and renaming straight away was enough to lose the tags. All four paths now carry the bindings unconditionally. Deleting orphaned bindings stays lazy, which is the one case where it costs nothing to wait.
- **Tags survive renames made outside the app.** The watcher saw an external rename as an unrelated disappearance plus appearance, and its orphan cleanup deleted the vanished path's tag bindings on the spot: renaming a tagged file in Explorer or Finder silently threw its tags away, and renaming a folder threw away the tags of everything under it. Renames are now recognized — the rename pairing the file watcher's debouncer already offers is switched on (its file-id cache was never populated, so on Windows and macOS it had nothing to match with), and a cross-directory move on Windows, which the OS reports as a plain remove plus add, is joined back by name, size and modification time when exactly one file matches. Tags follow in every recognized case, and the selection and tag panel follow with them. When several identical files move at once and there is no telling which went where, the bindings stay where they were instead of guessing — rename the files back and the tags are still there. An editor's backup-rename (`hero.png` becomes `hero.png.bak`, a fresh `hero.png` is written) keeps the tags on the living file, not the backup.
- **A folder renamed, moved or copied in from outside the app keeps its contents listed.** The OS reports one event for the folder and none for its files, and the watcher dropped directory events on the floor: everything under the old name vanished from the asset list and nothing under the new name replaced it until the next full rescan. A renamed folder now re-keys its subtree in place, and a folder that appears wholesale — moved or copied into the project — has its files read on the spot.
- **The right-click menu no longer runs off the bottom of the window.** It was placed against a fixed guess of its own size — 200 by 300 pixels — while what it actually contains varies with the file: an entry for the editor you mapped to that extension, and whichever of duplicate, move, copy and delete apply. Right-clicking a file low in the list therefore cut off the last item or two, and Delete, the bottom entry, could not be reached at all. The tag submenu had the same flaw twice over: it chose which side to open on by comparing against a 200-pixel width it never measured, and nothing considered its height, so with more than a dozen tags it hung off the bottom edge with the last of them unreachable. Both are now placed from their measured size, and the submenu is pulled up by however much would not fit.
- **The light theme no longer has dark holes in it.** The 3D preview drew its backdrop in one fixed near-black whatever the theme was, so a model sat in a black square inside a white panel — and the fullscreen viewer, which does let you choose a light or dark backdrop, always opened on dark under a button offering to turn the lights on. Both now start from the theme. Beside them, twenty-odd colours across the dialogs, the statistics tiles, the tag manager and the right-click menu were fixed shades picked against the dark theme: on white they measured between 1.5:1 and 2.8:1 against their background, where 4.5:1 is the readable floor — the folder icons in Move To, the green "done" banners after a batch rename, and the error lists in the delete and move dialogs were the worst of it. They now come from the theme's own colours. The Delete button gained a foreground that flips with the theme rather than being white in both: white on red measured 3.8:1 and failed in either one.
- **Tints that were never drawn now appear.** Thirty-five backgrounds, borders and dimmed labels across fourteen files asked for a partly-transparent version of a theme colour — the statistics tiles' icon chips, the export buttons, the error and success banners in the rename, batch-rename, move and delete dialogs, the tag chips, the play button over an audio waveform, the panel divider's hover. This app's Tailwind cannot apply an opacity to a colour held in a CSS variable, and rather than failing it emitted no rule at all, so every one of those surfaces has been drawing nothing and inheriting whatever was behind it. They now use the palette's own tint steps, which is also what makes them follow the theme.
- **The exported HTML report follows the reader's system theme, and prints on white.** The report was dark only — a light-theme user exported a black document — and its palette was a second, unrelated one: an indigo accent and Tailwind's default type colours, sharing nothing with the app the report came out of. It now carries the app's own palette in both themes, picks by `prefers-color-scheme`, and forces light with page-break control when printed. Asset-type badges are outlined rather than tinted, which also means every type is one colour value instead of two. A test now ties the eleven badge classes to the asset types the report emits: a new type without a matching rule used to ship as a silently unstyled badge.
- **Escape now dismisses one thing at a time.** A single press cleared both the previewed file and the search box — so a search term you had typed went away along with a selection you made with one click — while the checkbox selection, the state that has its own toolbar across the top of the list, survived it untouched. Escape now takes the topmost of those in turn: it cancels a running scan, or clears the checkbox selection, or closes the preview, or clears the search — one per press, in that order. Escape inside the search field still clears the field, as before.
- **A failed copy now says so.** The preview panel copied a path or a GUID through the browser's own clipboard interface, while the asset list's right-click menu went through the one the desktop framework provides — two mechanisms for the same job. The browser's is only permitted to run while a click is still being handled: measured in a packaged build, it refuses outright once that moment has passed, leaving the clipboard on its previous contents. The panel's only response was a line written to a console that a packaged application has nowhere to show — no checkmark, no message, nothing to distinguish a failed copy from a successful one. Both now go through the framework's clipboard, which carries no such restriction, and a failure is reported either way: in the preview panel's own inline error line, or as a notification from the list's menu.
- **A rename or move is refused up front when a stray engine sidecar blocks it.** Unity keeps an asset's identity in a `.meta` beside it, Godot in a `.uid` and its import settings in an `.import`, and the app carries all three through its own renames and moves. But the carry ran *after* the main file had already moved, and if a leftover sidecar happened to occupy the destination name, the failure went to a console a packaged app has nowhere to show: the file arrived, its identity stayed behind, the dialog said success, and Unity would silently mint a fresh GUID — breaking every reference to the asset. The collision is now checked before anything touches the disk, and the file is refused with a per-file error, the same way an occupied destination name already was. Undoing a rename gets the same check. Separately, a pure case rename (`hero.png` to `Hero.png`) used to refuse to carry the sidecar at all — the destination "already existed" because, on a case-insensitive disk, it was the sidecar itself; the carry now recognizes its own file and follows the case change.
- **The undo button describes the project you are looking at.** Switching projects while an undo or its state refresh was still in flight let the previous project's answer land on the new one: the header's button took the old project's enabled state and the history list showed the old project's entries, while clicking it would act on the current project. Late answers from a project you have already left are now dropped — the same rule the git refresh has followed all along — and the switch itself refetches the right state.
- **A search with a trailing space finds what it should.** The query was checked for emptiness with the spaces stripped but matched with them kept, so `icon ` — one accidental space after a paste or an input-method commit — quietly matched nothing. The filter, the command palette and the search-history dropdown all now strip the edges before matching; spaces inside the query still match paths literally.
- **Deleting the scoped folder outside the app no longer leaves a phantom scope bar.** When the folder the list was scoped to disappeared from disk, the scope fell back to "the project root as a directory" rather than "no scope" — every asset showed, but a scope bar hung over the list claiming a directory filter that filtered nothing, and the tree's root row and the bar disagreed about what was selected. The fallback is now the same "entire project" state that clicking the root row produces.
- **An unreadable `tidycraft.toml` fails the analysis instead of quietly ignoring your rules.** A missing config is the normal case and means defaults; a config that exists but cannot be read used to fall back to defaults with only a console line — the analysis then reported against thresholds you never set, and its clean result looked like your rules passing. Reading failure now fails the run with the reason, which is what the report exporters already did for the same file.
- **The AI cost preview prices the request that will actually be sent.** The estimate was built from an empty project: no tag context, no project framing, and one imaginary request regardless of size — while the real call re-sends the system prompt, your existing tags and their sample paths with every twenty-asset batch. The more tags the project had and the more assets you selected, the further under the truth the preview sat — the one direction a cost preview must never err. The estimate now carries the same context the request will, counts it once per batch, and prices GPT-5.4's images by the patch rule its family actually bills with instead of a flat rate belonging to an older model generation.

### Performance
- **Running the analysis no longer stalls everything else about the project.** The full analysis — including re-hashing every duplicate candidate and re-parsing engine files, seconds of file IO on a large project — ran while holding the project's lock, so the watcher's updates, a scan cancel and every other command on that project queued behind it; the report exporters did the same. All three now copy what they need under a brief lock and do the heavy work with the lock released. The result describes the moment the copy was taken, exactly as it already did — changes that used to queue behind the lock now simply apply while it runs, and the existing "analysis out of date" banner covers them.
- **The batch-rename preview stops rebuilding itself for nothing.** The dialog asks the backend what each selected file would be renamed to, and re-asks whenever the selection or the operation changes. The selection was handed to it as a freshly built list on every single render of the asset list behind it — so anything that redrew that list counted as a change, and every filesystem event under the project did: one for the watcher's update, a second for the tag reload it sets off. Measured with four files selected and five files touched on disk, that was ten identical preview requests nobody asked for, each one also pushing the preview itself a further debounce interval away; the same run now issues none. The cost scaled with how many files were selected, which is exactly backwards for the case the dialog exists to serve.

## [0.8.4] - 2026-08-07

### Changed
- **Godot's per-asset metadata files no longer count as assets.** A Godot project keeps one `.import` beside every imported file and, since 4.4, one `.uid` beside every script, so the asset list, the counts, the statistics and the analysis were all running at roughly twice their real size — padded with files you can neither preview nor act on. Unity's `.meta` had always been hidden this way; Godot's equivalents now are too. `project.godot` and the `.cfg` files stay listed: those are project files you may well want to find, not per-asset bookkeeping.
- **AI tagging rules that never ran now say so.** A `tidycraft.ai.toml` the app cannot parse falls back to the built-in suggestions, and a rule whose pattern this engine will not compile is skipped. Both were reported to standard error, which a bundled application has nowhere to write. The two kinds of suggestion look identical on screen, so the fallback read as a working rule set — and, since the same unreadable file also makes the panel report that you have never run learning, it went on inviting you to run it again with no hint why. Both now appear above the suggestions, with the reason.
- **The app icon shows the mark instead of its backdrop.** The gem took up 43% of the icon canvas and a dark rounded plate took the rest, so at the 32 pixels a taskbar or a file listing actually draws, the artwork came to about fourteen of them. The mark is now transparent and spans 94% of the canvas, the same on all three platforms. The amber halo is gone with the plate it was tuned against — without one it smears on light backgrounds — and macOS no longer keeps a separate inset master, because the Dock's 80.5% grid exists for plated square icons and this is not one. The mark in the app's own header follows the icon to the same 94% and loses the halo with it. Its light-theme facets were re-cut at the same time: they had drifted red-brown, which against a white header made the logo beside the title look like a different mark from the one on the taskbar.

### Fixed
- **Renaming a Godot asset now takes its metadata with it.** Godot stores each asset's import settings in a `.import` file beside it and, since 4.4, each script's identity in a `.uid` file — the same job Unity's `.meta` does, which the app has always carried. Godot's two were left behind: renaming a script broke every scene that referenced it by UID, and renaming a texture silently reset its compression, mipmap and filter settings to the defaults, with nothing on screen to say so. Moving, deleting and undoing had the same gap.
- **The 3D preview's vertex and mesh counts follow the interface language.** The line under a model read "768 vertices • 1 meshes" whatever the language was set to — untranslated, and wrong about the plural for the single-mesh models that make up most of them. It was written out twice, once under the inline preview and once in the fullscreen header, and both copies were equally wrong.
- **Closing a project stops its scan.** Closing dropped the project's state but not the scan running against it, so the walk continued to the end: on a large project, minutes of disk and CPU spent building a result nobody was left to receive.
- **The command palette keeps the selection where the keyboard put it.** Moving through the list with the arrow keys scrolls it, and whichever row slid under a stationary mouse pointer was read as a hover — so the highlight jumped back to the pointer, and Enter ran the command under the mouse instead of the one that appeared to be selected. Typing did the same, since re-filtering also moves rows under the pointer. The row beneath a resting pointer no longer lights up either: hover and the keyboard cursor draw the same highlight, and two of them said nothing about which one Enter would run. Moving the mouse hands the selection back to it immediately.
- **The command palette holds on to the keyboard.** Tab walked out of the open palette into the window behind it, leaving it on screen with the keyboard somewhere else, and closing it dropped focus rather than returning it to where you were. It now behaves like every other dialog in the app — focus stays inside and comes back on close — and is announced as a dialog rather than as anonymous content.
- **The sort column can be chosen from the keyboard.** Which column the asset list sorts by could only be set by clicking its header; the toolbar's control reverses the direction but cannot change the field, so with the keyboard alone the sort order was whatever it already was. Headers are now reachable by Tab and respond to Enter and Space.
- **A file replaced within one second is no longer missed.** Both the scan cache and the thumbnail cache decided what had changed from a modification time rounded down to the whole second, so re-exporting an image over itself — the ordinary way an art tool saves — left the previous dimensions, the previous format and the previous preview in place until the file was touched again. Times are now compared at full resolution, and file size joins the thumbnail key for the filesystems that only record whole seconds anyway. Both caches are rebuilt once on the first launch after this change.
- **The thumbnail cache no longer grows without limit.** Every edit to an image left its old thumbnail on disk permanently, and nothing but the Clear button in Settings ever removed one. The cache is now swept back to 256 MB at startup, oldest first.
- **The rename box holds the whole filename.** It held only the base name, with the extension pinned beside it as a label — so typing the name you could see, which is what Explorer and Finder train you to do, produced `hero.png.png`. The extension now sits in the field itself and starts outside the selection, so typing still replaces just the name; changing an extension on purpose works for the first time.

### Performance
- **Scrolling the gallery no longer floods the backend with thumbnail requests.** Every card asked for its thumbnail the moment it mounted, with nothing bounding how many could be outstanding — so flicking through a texture library put one request in flight per card scrolled past, hundreds of them, each a full image decode. Measured on 300 2048² textures: the backend grew from 112 threads to 574 (the runtime spawns one per queued task) and peaked at 5.7 GB, and the twenty-five cards actually on screen showed nothing at all for eighteen seconds, because they were queued behind every card the scroll had already left behind. Requests now go through a queue that keeps six in flight, and a card that scrolls away before its turn comes drops out of the queue — so what is left waiting is what you are looking at. The same scroll now peaks at 190 MB with no thread growth, and fills the viewport in about five seconds, drawing steadily rather than all at the end.
- **Large meshes no longer expand on every core at once.** Counting a model's vertices means holding its geometry in memory: `tobj` expands OBJ faces into a de-duplicated vertex buffer, the FBX reader builds the entire document tree, and a GLB keeps its binary chunk as a blob. Each one is bounded by the file it came from — but the scan parses in parallel, so the peak was that cost multiplied by the core count. A 67 MB OBJ measured 135 MB parsed on its own and 954 MB with eight in flight, which on a 20-core machine extrapolates past 2 GB for a project holding a few large meshes. Files of 32 MB or more now pass through a gate admitting two at a time; everything smaller — nearly every mesh in practice — keeps the full width of the thread pool. The gate costs no measurable time even for the files it holds: eight copies parsed no faster without it, memory pressure having eaten the parallelism it bought. `.gltf` is unaffected either way, since it reads accessor counts and leaves its buffers on disk.
- **Duplicate detection stops reading whole texture libraries.** Files were grouped by size and then hashed end to end, which does nothing for block-compressed textures: every image of the same dimensions and format has exactly the same byte count, so a project with five hundred 1024² maps read all five hundred in full on every analysis. Files are now separated by their first few kilobytes, and only those that still match are compared in full.

## [0.8.3] - 2026-08-04

### Added
- **A strict Content Security Policy.** The webview previously ran with no policy at all, so any script injected into it would have had the full asset protocol (every file on disk) and the whole command surface. Scripts are now restricted to the app's own bundle, and the preview chain is allowlisted precisely: thumbnails (`data:`), images and audio/video (`asset:`), and 3D model loading (which fetches over XHR, so it needs `connect-src`). Verified against a real build — note that `pnpm tauri dev` applies no CSP at all, so a CSP-breaking change cannot be caught in dev.
- **Unused-asset detection warns when it can't be trusted.** A project set to Force Binary asset serialization stores scenes and prefabs as binary, so their references are invisible to Tidycraft — and every asset only those files referenced looked unused. The panel now counts unreadable source files and, when any exist, says so above the list with a "don't delete based on this" warning and the setting to change. This was the one place the app could talk you into deleting assets that were in use.

### Changed
- **A misspelled key in `tidycraft.toml` is now reported instead of ignored.** Writing `max_sze = 512` under `[texture]` left `max_size` at its default and ran the analysis with settings you believed you had changed, with nothing on screen to say so. Unrecognised keys are now rejected by name, listing what that section accepts. The strictness is per-section — the file still carries `[project]` for AI Tagging, and anything a future feature adds alongside it.
- **Renames are refused when the resulting name would not survive Windows.** A trailing space or period is silently stripped by Windows on create, so the file would land under a name that no longer matches the one recorded in the undo history and the tag bindings — three views of one file quietly disagreeing. Device names (`CON`, `NUL`, `COM1` …) cannot be created at all, whatever extension follows. Both are refused on every platform, not only on Windows: a name minted on macOS ends up in the repository a Windows teammate has to check out.
- **Right-clicking outside the asset list no longer opens the webview's own menu.** Tidycraft's context menus covered asset rows, gallery cards and the tag panel header; everywhere else — sidebar, header, issue list, statistics, preview, empty space — a right-click produced the underlying browser engine's menu, offering Reload and Print in a shipped desktop app. That menu is now suppressed application-wide. Text fields keep theirs, so copy, paste and spelling corrections stay where you expect them.
- **Default forbidden characters now cover the Windows-illegal set** (`< > : " | ?`). The rule's stated purpose was portability, but the default list only held shell-awkward punctuation — the one category that is unambiguously a bug (such a file cannot be checked out on Windows at all) was the category it missed. Existing projects will report new issues on re-analysis; all are genuine.
- **Failures that used to be silent now say something.** Tag edits, cache clearing, and asset duplication reported errors only to the developer console — a failed tag delete looked exactly like nothing happening. They now surface as toasts. Backend writes that used to be discarded are logged instead: tags, the scan cache, the undo history, and the AI suggestion cache — the last of which matters most, since a cache that can never be written means every AI tagging run is billed in full, forever, with nothing to explain why.
- **The Claude model list is current again.** The dropdown offered a generation that has since been superseded; it now leads with Claude Sonnet 5 and offers Opus 5 alongside Haiku 4.5, and the cost estimator prices them — including the higher per-image token ceiling the current models' larger input resolution implies. Models offered previously stay priced, so a pinned configuration keeps its estimate instead of falling back to "unknown". A saved setting is untouched by this: only new configurations pick up the new default.
- **The interface stays responsive during a scan.** The keyboard-shortcut hook subscribed the entire application to every store change, so each progress tick — ten a second — re-rendered the whole tree, undoing the selective subscriptions the rest of the app is careful to use. The filter panel in the header did the same and re-walked every asset in the project on each of those renders.
- **Minimum Rust version is now 1.88** (was declared as 1.75). This is the floor the dependency graph already imposed; the old declaration simply could not be honored. Building has not changed for anyone on a current toolchain.
- **Issue titles, explanations and suggestions now follow the interface language.** The analysis panel's rule names and descriptions were English regardless of the language setting, sitting next to Chinese labels — the most visible rough edge for anyone not reading English. All 23 rules are translated, and a rule that a future language hasn't reached yet falls back to its English text rather than showing a placeholder. The exported HTML report picks up the same titles and explanations, though its own headings, labels and column names are still English. The JSON export stays English throughout, as a stable contract for scripts. It does pick up one addition: every issue that interpolates a value into its message or suggestion now carries those values in a machine-readable `args` object (21 of the 23 rules), for anyone parsing that export who wants to render the text themselves. Audio sample-rate issues also stop printing the expected rates in Rust's debug form (`[44100, 48000]`).

### Fixed
- **The cost estimate for GPT-4o mini was 33× too low.** OpenAI bills that model's images at 2833 tokens rather than 85 — the count is scaled up to match its 33×-cheaper per-token price, so an image costs about the same dollars on either model. The estimator charged 85, which is the direction it explicitly promises never to err in: the number shown before you approve a paid run was a small fraction of the real one.
- **A local vision model no longer silently loses the start of its prompt.** Ollama attaches images outside the text, so they were budgeted as zero context while the model expands each into over a thousand tokens. The window was sized for the text alone, and Ollama's answer to a too-small window is to drop the front of the prompt — the system prompt first, which is exactly what that setting exists to prevent. Images are now counted, and a request that still doesn't fit says so in the log instead of failing quietly.
- **A reply cut short by a local model is reported as such.** Ollama says so in `done_reason`, which was ignored, so the truncated JSON reached the parser and came back as a complaint about malformed output — pointing at the model rather than at the request size, which is the part you can change. Both cloud providers already handled this.
- **A refused OpenAI request explains itself.** When the model declines, it returns its reason in a separate field and leaves the content empty; the empty content failed to deserialize, so the call surfaced as "failed to parse provider response" — about a reply that was perfectly well-formed — and discarded the one sentence that said what happened.
- **"The provider is overloaded" no longer reads as "check your connection."** Anthropic's 529 (and the generic 503) mean the service is busy and waiting is the fix, but they were classed as network errors, whose message sends you to inspect the one thing that isn't wrong.
- **Sprite atlases and eight other asset types now count as references.** Only seven Unity file types were read for the references they hold, so a sprite packed into an atlas, a texture used by a terrain layer, a clip in a Timeline — anything whose only referrer was one of the missing types — was reported as unused. That list is what people delete from. The parser and the scan now share one definition of "file that can point at another asset" instead of keeping two lists that had already drifted apart once.
- **A PBR set whose base colour comes from a packed texture can be located.** When the trigger channel was satisfied only by a packed map (an `_ORM`-style suffix covering several channels at once), the reported issue carried no file path, so clicking Locate did nothing and gave no reason.
- **Moving a file into the folder it is already in stops reporting a conflict.** The destination check compared paths as text while the rename path asks the filesystem for identity, so any other spelling of the same folder — a case variant, a symlink, a `..` — produced "Target already exists" about the file being moved. Undoing a move had the same gap, and there it was permanent: a batch where everything fails is not consumed, so the error returned on every retry.
- **Startup language follows your first preference, not any preference.** The detector asked "is Chinese anywhere in the list", so a system set to English first and Chinese second booted into Chinese. It now takes the first entry it supports, skipping over locales that don't ship.
- **The model dropdown no longer renders empty.** A cloud provider configured with a model outside the curated list — an older pin, or a config written by a newer release — matched no option and displayed blank, reading as "nothing selected" while that model was still the one being called. The configured value is now always among the options, which is how the Ollama list already behaved.
- **A file-size filter of 0 stays visible in its box.** Typing `0` set the filter and then displayed nothing, leaving the "filters active" marker lit with no visible cause.
- **Locating a root-level asset no longer leaves a stray scope bar.** The Locate action set the directory scope without the normalisation the sidebar applies, so the project root arrived as a filter that means the same thing as no filter.
- **The unused-asset list caps how many rows it renders** (200, with the remainder counted below), the same guard the duplicate-group list already had. An unpruned project can report tens of thousands of files, and each one mounted a row and a button.
- **Opening a Unity project's `Assets` folder is recognised as Unity.** Everything that identifies a Unity project — `ProjectSettings/`, `Library/PackageCache` — sits *above* `Assets/`, so pointing Tidycraft at that folder (or anything inside it, which is how most people navigate to their art) quietly produced a "Generic" project: no dependency graph, no unused-asset detection, no prefab components, and no message saying why. Detection now looks up the tree, and the package cache is read from the project root it finds, so package references keep resolving instead of turning into a wall of broken-reference warnings.
- **Godot references match assets whose names use a different Unicode encoding.** The same accented or non-Latin file name can be stored decomposed on disk and composed inside a scene file — identical to read, different as text — which made the rename guard report "nothing references this" for a file a scene did reference. Renaming on that advice broke the link, which is the one thing the guard exists to prevent; unused-asset detection had the same blind spot and invited deleting files that were in use.
- **A corrupt undo history is preserved instead of quietly discarded.** An unreadable history file was treated as "no history", and the next operation saved over it — so a recoverable file became an unrecoverable one, without a word. It is now moved aside as `.corrupt` (keeping the first such backup) and the reason is logged, matching how the tags file has always behaved.
- **One malformed entry in a `.uproject` no longer hides the whole project.** A single plugin or module entry missing a field made the entire file fail to parse, so the Unreal engine card, its version and its plugin list vanished from the interface. Unreadable entries are now skipped and logged individually.
- **PascalCase no longer rejects acronyms.** With `case_style = "PascalCase"`, `HUD.png` and `UI.png` were reported as violations and the offered fix was `Hud.png` — throwing away the acronym to satisfy a check they already met. A one-letter name like `A.png` was flagged with no possible fix at all, so the issue could never be cleared.
- **Assets that follow a prefix convention are no longer reported as misnamed.** With both a type prefix (e.g. `T_`) and a case style configured, the case check ran against the whole filename — and no case style accepts `T_`, so every correctly named `T_rock.png` was flagged. Worse, accepting the suggested fix produced a name that violated the prefix rule, whose fix violated the case rule again: applied repeatedly, names grew without ever settling. Case is now checked past the configured prefix, and the prefix is preserved by the fix.
- **Ignoring a folder no longer makes everything that references it look broken.** `[ignore]` dropped matching assets before analysis entirely, so ignoring vendored directories — the sample config's own example — removed their GUIDs from the project's known set and every prefab or material pointing at them reported a dangling reference. Ignored assets still count as existing; ignoring a *referencing* file still suppresses its findings as documented. Duplicate, PBR-set and DCC-source checks are unchanged.
- **Tags no longer vanish during large rename or move batches.** The disk operations ran with the project unlocked and tag bindings were migrated only afterwards, so the filesystem watcher could see the old paths already gone and reap their tags as orphans — silently, and only on batches long enough to outlast its debounce window. Each file's rename and its tag migration now share one lock window.
- **A malformed `project.godot` no longer takes the app down.** A half-typed value ending in a lone quote hit an out-of-bounds slice, and release builds abort on panic, so this exited the whole application rather than failing one command.
- **An undo that reverts nothing stays undoable.** The entry was consumed even when every file failed — typically because they were open in another application — so the operation became unrecoverable after fixing the cause. Partial success still consumes the entry.
- **Fix-it and Move now leave a working undo.** Both recorded an undo batch on the backend but never refreshed the frontend, so the header's undo button stayed disabled: Fix-it was recoverable only during its ~5-second toast, and Move — which shows no toast — had no reachable undo at all.
- **Dependency graph edges no longer curve back on themselves.** Edges entered and left the long sides of each node while the layout ran left-to-right; they now follow the layout direction.
- **A symlinked directory no longer appears in the tree.** The tree followed links while the asset scan does not, so linked folders showed up holding files that could never be listed — and a symlink loop made the walk recurse until the OS stopped it.
- **The largest-files list translates its type badges.**
- **The macOS app icon no longer sits a size larger than everything else in the Dock.** macOS draws app icons on a grid that reserves a transparent margin for the shadow the system puts behind them: the rounded square occupies about 80% of the image, not all of it. Tidycraft's icon filled its canvas edge to edge, so it rendered about a quarter wider than every stock application beside it. Only the macOS icon set changed; the Windows and Linux icons keep their current framing, which those platforms expect.

- Refreshed dependencies with published advisories: vite, postcss, @babel/core (build-time only, but the vite issue is exploitable against the dev server), plus serde_with and quinn-proto.

## [0.0.1] — Alpha

This is the initial public alpha. Everything below has shipped and is considered stable for normal use; bugs are expected and welcome via [GitHub Issues](https://github.com/Lynthar/Tidycraft/issues).

### Scanning & state
- Parallel `walkdir + rayon` scan with per-asset metadata extraction (image dims, model vertex/face/material counts, audio sample rate / duration / channels, video codec / framerate).
- Incremental scan cache keyed by `(mtime, size)` on disk under `dirs::cache_dir()/tidycraft/scans/`.
- Multi-project workspace: open several projects simultaneously, switch with `ProjectSwitcher`, cross-session restore of open paths.
- Live filesystem watcher (`notify-debouncer-full`, 500ms debounce) — external file changes refresh the asset list automatically.
- Engine detection: Unity / Unreal / Godot / generic, with engine-specific parsers (`.meta` GUIDs, `.uproject`, `project.godot`).

### Analysis
- Rule engine with per-asset families: `naming`, `texture`, `texture.color_space`, `model`, `audio`.
- Cross-asset checks: `duplicate` (SHA256), `missing_reference` (Unity GUID lookup), `pbr_set` (per-folder texture group completeness, with packed channels — ORM / MRA / RMA).
- Out-of-box defaults are minimal — only real bug checks fire by default; stylistic conventions (PoT, file-size, vertex budgets) are opt-in via `tidycraft.toml`.
- Glob-based `[ignore]` patterns for vendored / generated paths.
- Per-project `tidycraft.toml`; in-app **Settings → Analysis Rules → Edit** opens the file in the OS editor.
- Issue list with severity filter, group-by-rule, virtualized rendering for 10k+ issues, JSON / CSV / HTML export.

### Tag system
- Per-project tags, persisted to `.tidycraft-tags.json` at project root.
- Multi-select tag filter; rename / move syncs tag bindings; deleted files reaped by watcher.
- Heuristic tag suggestions (filename token / dimension + PBR channel / path segment), surfaced in the Sidebar **AI Tag** button.

### Asset browsing
- List + Gallery (grid) views with `@tanstack/react-virtual` virtualization.
- Thumbnail preview with disk cache (PNG / JPG / GIF / BMP / TGA).
- 3D model preview via Three.js: glTF / GLB / FBX / OBJ (+MTL) / DAE / 3DS. `.blend` recognized but routed to a "please export to GLB" message.
- Video preview (MP4 / WebM / MOV / AVI / MKV / M4V).
- Audio preview with waveform.
- Command Palette (⌘K / Ctrl+K) — quick navigation, filters, actions.

### File operations
- Safe delete to OS trash, move, copy, duplicate; all watcher-driven (no rescan needed).
- Batch rename with persistent undo (50-entry stack).
- Tags follow file across rename / move; orphan tag bindings cleaned automatically when files vanish.

### External editors
- Settings → External Editors maps file extensions to specific binaries (Photoshop / Blender / Audacity / etc.).
- AssetPreview's open button uses the mapping; falls back to OS default app.
- Routed through `tauri-plugin-opener` so Windows codepage / quoting / `%`-character paths work correctly.

### Cross-platform
- Windows / macOS / Linux supported.
- macOS shortcut display uses `⌘ ⇧` glyphs; Windows / Linux show `Ctrl+Shift+`.
- Path normalization (forward-slash everywhere on the boundary); `lib/pathUtils.ts` for shared helpers.
- Show in File Manager (renamed from "Reveal in Finder") works correctly on all three platforms.

### Git integration
- Branch info, ahead/behind counts, per-file change status badges.
- Toggleable in Settings → Git.

### i18n
- English + Simplified Chinese.

### Known limitations (alpha)
- LLM-backed semantic tagging is **not** in this build; the AI Tag panel is heuristic only.
- macOS / Windows binaries are **not code-signed** in v0.0.1 — first-launch warnings are expected.
- Tested up to ~50k assets per project; larger projects should work but may be slow.
- 3D preview limitations on paths with spaces / non-ASCII characters (Tauri asset protocol quirk; not Tidycraft-fixable).
